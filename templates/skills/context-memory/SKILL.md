# 컨텍스트 그래프 기록 절차

⛔ **판단을 매번 즉흥으로 하지 않는다.** 세션마다 달라지면 저장소가 일관성을 잃는다.

## 0. 먼저 조회한다 — 이미 있는지

```bash
node tools/graph-find.mjs <어근…>        # 어근을 짧게, 여러 개
node tools/graph-find.mjs --files <경로>
```

있으면 **새로 만들지 말고 판단한다** → §4(무효화)로.

## 1. 무엇을 기록하나 — 이 표가 유일한 기준

> **규칙으로 만들 수 있으면 질의 때 만들고, 재조회로 얻을 수 있으면 명령을 적고,
> 둘 다 아니면 그때 기록한다.**

| 기록한다 ⭐ | 기록하지 않는다 ⛔ |
|---|---|
| 현업 용어 → 코드 식별자 (`필실천`→`eap`) | 조사·띄어쓰기 변형 (훅이 질의 쪽에서 만든다) |
| 함정 — 왜 그 파일이었나, 무엇에 걸렸나 | 스키마·컬럼 목록 (DB 조회로 나온다 → 조회 **명령**을 적는다) |
| **부재 사실** (FK 0건, INSERT 매퍼 없음) | 파일 목록만 (git 으로 알 수 있다) |
| 사람의 판정 (이 기록은 이제 틀렸다) | 검증 안 된 추측 |
| 중단·미구현 (어디까지 알아냈고 왜 멈췄나) | 재생성되는 값(건수·경로) |

⛔ **`terms` 와 `note` 가 이 저장소의 값 전부다.** 둘을 대충 적으면 git 의 열등한 사본이다.
⛔ **키는 사용자의 말, 값은 시스템의 실체.** 공식 용어를 키로 적으면 다음에도 못 찾는다.

## 2. 어떤 형태로 — 건수가 갈린다

| 상황 | 형태 | 이유 |
|---|---|---|
| 작업 1건을 마쳤다 | `graph-append` 기록 1건 | 요구→파일 간선 |
| 대화 중 용어 1개를 알아냈다 | `graph-alias` 1줄 | 마찰이 낮아야 실제로 적는다 |
| 문서·DB 에서 용어 20~30개를 뽑았다 | **도메인별 기록 1건에 몰아넣는다** | 2단 색인은 **기록 수**에 비례한다 — 30건으로 쪼개면 색인이 3배 |

```bash
node tools/graph-alias.mjs <사용자의 말> "<실체>" [--file 경로]… [--note 함정]

node tools/graph-append.mjs <<'JSON'
{"req":"용어 사전: <도메인>","terms":{"용어":"실체", …},"tables":["apms.…"],"files":[…],"note":"함정"}
JSON
```

⛔ **`files` 에 `:256` 같은 줄번호를 붙이지 않는다.** 존재 검사·역방향 조회가 빗나간다.

### ⭐ 긴 것은 파일로 두고 기록에는 길잡이만

운영 쿼리·절차서·설정 원문처럼 **긴 덩어리는 `note` 에 베끼지 않는다.**
`tools/graph/sql/` 같은 곳에 파일로 두고, 기록에는 **어디에 있고 · 언제 쓰고 · 무엇에 걸리는지**만 적는다.

```
tools/graph/sql/<이름>.sql   원문 + 머리에 사용법·함정 주석
기록의 files 에 그 경로       --check 가 존재를 검사해준다
기록의 terms·note 에 길잡이   「3개 절차가 이 파일을 공유한다」 같은 것
```

⛔ **베끼면 반드시 어긋난다** — 원문이 바뀌어도 기록은 안 바뀐다.
⭐ 파일 머리 주석에 **대상 한정 방법과 안 지켰을 때 무슨 일이 나는지**를 적는다.
예: 「주석 두 줄을 안 풀면 status='Y' 인 전 조직이 갱신된다」.

### ⛔ 용어 키는 그 용어의 정본 기록에만

도구·설정 작업 기록에 도메인 용어를 *예시로* 넣으면 정본을 순위에서 밀어낸다.
예시는 `note` 나 `req` 본문에 쓴다 — 거기도 검색되지만 가중치가 낮아 정본을 밀지 않는다.

⚠️ 이 규칙은 **예시**에만 적용된다. 그 기록이 진짜로 그 용어에 대한 것이면 키로 넣는 게 맞다.
⛔ **반대 방향도 놓치지 말 것** — 제거된 기능·바뀐 워딩을 `note` 에만 두면 조회가 약해진다.
그때는 키로 올리되 **값의 맨 앞에 「⛔ 제거됨」·「⚠️ 이후 바뀜」을 붙인다**(실측: 「조직건전성」·「SCM」·「ESG」가
`note` 에만 있어 못 찾다가 별칭으로 올려 해결).

## 3. 근거 등급 — 어디까지 확인했나를 적는다

| 등급 | 표기 | 예 |
|---|---|---|
| 실행 검증 | 그냥 적는다 | 테스트가 돌았다, 화면에서 확인했다 |
| 코드·스키마 실측 | 「실측」 + 재조회 명령 | 매퍼 참조 수, `psql` 결과 |
| 조사만 | **`(조사만, 미실행)`** 를 `req` 에 | DB 변경안을 짜기만 했다 |
| 미확정 | `note` 에 **⚠️ 미확정** 과 남은 의문 | 어느 쪽이 정본인지 못 정했다 |

⛔ **단일 증거로 단정하지 않는다.** 예: 「행 0」만으로 죽은 테이블이라 하지 않는다 —
로컬 DB 는 대부분 비어 있다. **행 0 + 매퍼 참조 0** 처럼 교차 확인한 것만 단정한다.

## 4. 갱신·무효화 — 새 기록 추가로 갈음하지 않는다

판단 기준은 하나다: **「이 기록을 그대로 믿고 작업하면 틀리나」** — 틀리면 낡은 것이다.

| 낡은 것 | 할 일 |
|---|---|
| 이전 기록 전체가 무효 | 새 기록에 `"supersedes":"<이전 req>"` |
| 일부만 낡음 | 새 기록에 정정 사실 + `note` 에 무엇이 바뀌었는지 |
| `spec-map.md` · `spec.md` 와 어긋남 | 그 문서를 고친다 (그래프에 베끼지 않는다) |

⛔ **별개 작업이면 `supersedes` 를 비운다.** 같은 화면을 만졌다고 다 대체가 아니다.
⚠️ `supersedes` 는 `req` **문자열**로 잇는다 — 한 글자만 달라도 끊긴다.

### ⛔⛔ 과거를 소급 기록할 때 — 최신을 덮지 않는다

이력·업무목록·문서를 **최신→과거 순으로 훑을 때** 가장 위험한 실수다.
`supersedes` 는 기록 순서(줄 번호)로 판정하므로, **과거 사실을 나중에 append 하면 그것이 「최신」으로 들어앉는다.**

| 규칙 | |
|---|---|
| ⛔ **과거 기록에 `supersedes` 를 붙이지 않는다** | 대체는 **나중에 일어난 일**이 먼저 일어난 일을 무효화할 때만 쓴다 |
| ⛔ **`date` 를 반드시 그 일이 일어난 날로 준다** | 안 주면 오늘이 들어가 시간축이 뒤집힌다 |
| ⭐ **최신 기록과 어긋나면 과거 쪽에 표기한다** | 「⚠️ 이후 <날짜>에 <무엇>으로 바뀜 — 최신은 [그 기록] 참조」 |
| ⛔ **과거 사실을 용어 키로 올리지 않는다** | 죽은 기능·옛 컬럼명은 `note` 에 쓴다. 용어 키로 올리면 조회 상위를 과거가 차지한다 |

⭐ **판단 기준: 「지금 이 시점에 이 말이 참인가」** — 아니면 과거 사실이고, 그때는 **현재형으로 쓰지 않는다.**
예: 「미래혁신팀이 담당이다」(✗) → 「2026-09-03 까지는 미래혁신팀이었다, 현재는 기획팀」(✓)

## 5. 끝내기 전 — 반드시

```bash
node tools/graph-find.mjs --check    # ⛔ exit 0 이어야 한다 (사슬·경로·용어 선점)
node tools/graph-find.mjs <방금 넣은 용어>   # 걸리는가
```

⭐ 사용자에게 **작업 파일 목록을 보고할 때 그래프 기록도 한 세트로** 보고한다.
남길 게 없다고 판단했으면 **그 판단을 한 줄로 밝힌다** — 조용히 건너뛰지 않는다.

## 6. 커버리지가 궁금하면

```bash
node tools/graph-find.mjs --promote spec-map.md   # 3회 이상 쓰였는데 정본에 없는 용어
node tools/graph-view.mjs                         # 전체를 브라우저 한 장으로
```

⚠️ **그래프는 미지의 영역을 빠르게 만들지 못한다. 반복되는 영역을 빠르게 만든다.**
새 영역은 여전히 정상 탐색 비용이 든다 — 그때 용어를 등록해야 다음이 빨라진다.
