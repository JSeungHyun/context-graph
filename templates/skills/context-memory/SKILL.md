# 컨텍스트 그래프 기록 절차

⛔ **판단을 매번 즉흥으로 하지 않는다.** 세션마다 달라지면 저장소가 일관성을 잃는다.

## 0. 먼저 조회한다 — 이미 있는지

```bash
node tools/graph-find.mjs <어근…>        # 어근을 짧게, 여러 개
node tools/graph-find.mjs --files <경로>
```

있으면 **새로 만들지 말고 판단한다** → §4(무효화)로.

## 1. 무엇을 기록하나 — 이 표가 유일한 기준

> **규칙으로 만들 수 있으면 질의 때 만들고, 재조회로 얻을 수 있으면 명령을 적고,
> 둘 다 아니면 그때 기록한다.**

| 기록한다 ⭐ | 기록하지 않는다 ⛔ |
|---|---|
| 현업 용어 → 코드 식별자 (`필실천`→`eap`) | 조사·띄어쓰기 변형 (훅이 질의 쪽에서 만든다) |
| 함정 — 왜 그 파일이었나, 무엇에 걸렸나 | 스키마·컬럼 목록 (DB 조회로 나온다 → 조회 **명령**을 적는다) |
| **부재 사실** (FK 0건, INSERT 매퍼 없음) | 파일 목록만 (git 으로 알 수 있다) |
| 사람의 판정 (이 기록은 이제 틀렸다) | 검증 안 된 추측 |
| 중단·미구현 (어디까지 알아냈고 왜 멈췄나) — ⛔ `note` 를 `⏸` 로 시작 | 재생성되는 값(건수·경로) |

⛔ **`terms` 와 `note` 가 이 저장소의 값 전부다.** 둘을 대충 적으면 git 의 열등한 사본이다.
⛔ **키는 사용자의 말, 값은 시스템의 실체.** 공식 용어를 키로 적으면 다음에도 못 찾는다.

### ⛔⛔ 행동을 바꿔야 하는 것은 그래프가 아니라 지침에 넣는다

⚠️ 실측 사례: 새 탐색 방법(DB 코멘트 확인)을 알아내 **그래프 용어로만 적었더니 바로 다음 턴에
그 방법을 안 쓰고 추측으로 답했다.** 그래프 용어는 **그 주제를 물을 때만** 걸리고, 지침은 매 세션 로드된다.

| 성격 | 어디에 |
|---|---|
| **사실** — 이 용어가 무엇인가, 이 컬럼이 무엇을 담나, 무엇에 걸렸나 | 그래프 |
| **행동** — 앞으로 무엇을 먼저 볼까, 무엇을 하지 말까 | **지침 파일**(`AGENTS.md` 등) |

⭐ 판단 기준: **「다음 세션이 이걸 안 읽으면 같은 실수를 하나」** — 그렇다면 지침이다.

### ⛔ 「컨텍스트가 부족하니 자동으로 채우자」가 나오면 — 원천으로 가른다

금지가 아니라 **무엇을 추출하나**가 판정 기준이다.

| 원천 | 판정 | 왜 |
|---|---|---|
| **사람이 쓴 것** — 티켓 원문·인수인계 문서·담당자 답변 | ⭕ **옮겨도 된다** | 원문이 남아 검증 가능하고 진술은 변하지 않는다 |
| **코드 구조** — 경로·건수·관통 세트·컬럼 목록 | ⛔ **기록하지 않고 도구로 조회한다** | 변한다. 베낀 사본은 반드시 어긋난다 |
| **해석·인과·「실제로 쓰나」** | ⛔ **자동 추출 금지** | 실패 모드가 빈 칸이 아니라 **그럴듯한 오답**이고, 훅이 권위를 붙여 내보낸다 |

⭐ **공백을 채우려면 목록부터 만든다** — `미확정`·`미확인` 표기를 긁으면 절반은 이미 있다.
⛔ 목록 없이 「전체를 한 번 채운다」로 시작하지 않는다.

⭐ **문서를 원천으로 쓰면 「어떻게 열었나」도 기록한다.** 다음 세션이 파일을 못 열어 멈춘다 —
암호·인코딩·필요한 도구를 한 줄 남긴다. ⛔ **암호 자체는 적지 않는다**(「문서 N페이지」·「사용자에게 받는다」로).
⚠️ 실측 함정: 암호 걸린 Office 파일은 zip 해제가 안 되고(OLE2 헤더) COM 자동화로 열어야 하며,
PowerShell 은 비ASCII 경로를 잘못 읽으므로 **ASCII 경로로 복사한 뒤** 여는 편이 빠르다.

## 2. 어떤 형태로 — 건수가 갈린다

| 상황 | 형태 | 이유 |
|---|---|---|
| 작업 1건을 마쳤다 | `graph-append` 기록 1건 | 요구→파일 간선 |
| 대화 중 용어 1개를 알아냈다 | `graph-alias` 1줄 | 마찰이 낮아야 실제로 적는다 |
| 문서·DB 에서 용어 20~30개를 뽑았다 | **도메인별 기록 1건에 몰아넣는다** | 2단 색인은 **기록 수**에 비례한다 — 30건으로 쪼개면 색인이 3배 |

```bash
node tools/graph-alias.mjs <사용자의 말> "<실체>" [--file 경로]… [--note 함정]

node tools/graph-append.mjs <<'JSON'
{"req":"용어 사전: <도메인>","terms":{"용어":"실체", …},"tables":["apms.…"],"files":[…],"note":"함정"}
JSON
```

⛔ **`files` 에 `:256` 같은 줄번호를 붙이지 않는다.** 존재 검사·역방향 조회가 빗나간다.

### ⭐ 긴 것은 파일로 두고 기록에는 길잡이만

운영 쿼리·절차서·설정 원문처럼 **긴 덩어리는 `note` 에 베끼지 않는다.**
`tools/graph/sql/` 같은 곳에 파일로 두고, 기록에는 **어디에 있고 · 언제 쓰고 · 무엇에 걸리는지**만 적는다.

```
tools/graph/sql/<이름>.sql   원문 + 머리에 사용법·함정 주석
기록의 files 에 그 경로       --check 가 존재를 검사해준다
기록의 terms·note 에 길잡이   「3개 절차가 이 파일을 공유한다」 같은 것
```

⛔ **베끼면 반드시 어긋난다** — 원문이 바뀌어도 기록은 안 바뀐다.
⭐ 파일 머리 주석에 **대상 한정 방법과 안 지켰을 때 무슨 일이 나는지**를 적는다.
예: 「주석 두 줄을 안 풀면 status='Y' 인 전 조직이 갱신된다」.

### ⭐⭐ 절차는 정본 1건 + 템플릿 파일 — 사실 조각으로 쌓지 않는다

반복 운영 절차(「…요건이 오면 뭘 확인하고 어디에 넣나」)는 **`req` 가 `정본: ` 으로 시작하는 기록 1건**이 답이다.
사실 조각 여러 건에 흩어지면 찾은 뒤에도 조립이 답변 비용이 된다 — 실측(2026-09-14): 절차 하나가 5건에 흩어져 있어
기록이 있는데도 도구 호출 7회가 들었고, 사용자가 「매번 이 비용이면 이 구조를 채택할 이유가 없다」고 했다.

| 정본에 넣는 것 | |
|---|---|
| 절차 단계 | 확인 → 반영 → 검증 순서. 화면으로 되는 것과 DB 로 하는 것의 경계 |
| 템플릿 파일 | `tools/graph/sql/<절차>_insert.sql` 류 — **INSERT 컬럼 목록까지** 적는다. 낡음은 `node tools/sql-template-check.mjs <파일>` 로 잰다(⛔ INSERT 만 검사한다. UPDATE 템플릿은 컬럼을 한 번 확인해 적는다) |
| 현업 표현 키 | 이슈 트래커 제목에서 뽑은 **사용자의 말**을 용어 키로. 짧은 낱말(2~4자)도 넣는다 — 광역 용어사전과 같은 키를 가지면 동점에서 최신인 정본이 이긴다 |
| 통합 | `"supersedes":["<req1>","<req2>",…]` 배열로 조각을 전부 무효화한다 |
| 미확정 | 확인 안 된 것은 `⚠️ 미확정` 으로 표기해 남긴다 — 정본이라고 추측으로 채우지 않는다 |

⭐ 광역 용어사전의 해당 항목은 지우지 않고 **값 끝에 「⭐ 정본은 […] 참조 (날짜)」를 제자리로 붙인다** — 사전은 어휘 층으로 남고 절차는 정본으로 간다.
⭐ 정본의 동의어 키 추가·항목 보강은 **제자리에서** 고친다(날짜 표기). 내용이 뒤집히는 정정만 새 정본 + `supersedes`.
⭐ 훅은 정본이 1위면 카드 1장만 주입한다 — 정본 카드가 곧 절차라 길어도 그것 하나로 끝난다.
⭐ 만든 뒤 `node tools/graph-measure.mjs "<현업 표현 정규식>"` 으로 그 주제 티켓 제목에서 정본이 1위인지 잰다.

### ⛔ 용어 키는 그 용어의 정본 기록에만

도구·설정 작업 기록에 도메인 용어를 *예시로* 넣으면 정본을 순위에서 밀어낸다.

⛔⛔ **예시 낱말은 어느 필드에도 넣지 않는다 — 전 필드가 색인된다.** `scoreDetail` 이 `req`·용어 키·
**용어 값**·`tables`·`files`·**`note`** 를 전부 건초더미에 넣는다. 색인 안 되는 필드는 **없다.**
⚠️ 이 줄은 원래 「예시는 `note` 나 `req` 에 쓴다 — 가중치가 낮아 정본을 밀지 않는다」였다. **틀렸다.**
가중치가 낮은 건 맞지만 문제는 순위가 아니라 **도달**이다 — 그 기록이 아무 상관 없는 낱말로 검색에
걸려서, 무관한 프롬프트가 색인 덤프를 받는다. 2026-09-09 에 그 조언대로 적어 세 번 오염시켰다.
⭐ 예시가 필요하면 **낱말이 아니라 성격을 쓴다** — 사용자 발화를 인용하지 말고
「업무 내용이 없는 짧은 대화 발화」처럼 분류로 적는다.
⭐ 자기점검: 넣은 뒤 그 예시 낱말로 조회한다. 엉뚱한 게 1위면 오염된 것이니 그 자리에서 고친다.

⚠️ 이 규칙은 **예시**에만 적용된다. 그 기록이 진짜로 그 용어에 대한 것이면 키로 넣는 게 맞다.
⛔ **반대 방향도 놓치지 말 것** — 제거된 기능·바뀐 워딩을 `note` 에만 두면 조회가 약해진다.
그때는 키로 올리되 **값의 맨 앞에 「⛔ 제거됨」·「⚠️ 이후 바뀜」을 붙인다**(실측: 「조직건전성」·「SCM」·「ESG」가
`note` 에만 있어 못 찾다가 별칭으로 올려 해결).

## 3. 근거 등급 — 어디까지 확인했나를 적는다

| 등급 | 표기 | 예 |
|---|---|---|
| 실행 검증 | 그냥 적는다 | 테스트가 돌았다, 화면에서 확인했다 |
| 코드·스키마 실측 | 「실측」 + 재조회 명령 | 매퍼 참조 수, `psql` 결과 |
| 조사만 | **`(조사만, 미실행)`** 를 `req` 에 | DB 변경안을 짜기만 했다 |
| 미확정 | `note` 에 **⚠️ 미확정** 과 남은 의문 | 어느 쪽이 정본인지 못 정했다 |

⛔ **단일 증거로 단정하지 않는다.** 예: 「행 0」만으로 죽은 테이블이라 하지 않는다 —
로컬 DB 는 대부분 비어 있다. **행 0 + 매퍼 참조 0** 처럼 교차 확인한 것만 단정한다.

## 4. 갱신·무효화 — 새 기록 추가로 갈음하지 않는다

판단 기준은 하나다: **「이 기록을 그대로 믿고 작업하면 틀리나」** — 틀리면 낡은 것이다.

| 낡은 것 | 할 일 |
|---|---|
| 이전 기록 전체가 무효 | 새 기록에 `"supersedes":"<이전 req>"` |
| **같은 주제의 살아있는 기록이 2건 이상** | ⭐ 사실을 더 쌓지 않고 **정본 1건으로 통합**한다 — `req` 는 `정본: ` 으로 시작, `"supersedes":["<req1>","<req2>",…]` 배열로 전부 무효화 (2026-09-14) |
| 일부만 낡음 | 새 기록에 정정 사실 + `note` 에 무엇이 바뀌었는지 |
| **한 대목만 낡음**(미확정이 풀렸다·값이 틀렸다) | ⭐ **그 대목을 원래 기록에서 직접 고친다** (아래) |
| `spec-map.md` · `spec.md` 와 어긋남 | 그 문서를 고친다 (그래프에 베끼지 않는다) |

⛔ **별개 작업이면 `supersedes` 를 비운다.** 같은 화면을 만졌다고 다 대체가 아니다.
⚠️ `supersedes` 는 `req` **문자열**로 잇는다 — 한 글자만 달라도 끊긴다. 배열이면 원소마다 그렇다.

#### ⛔⛔ 미확정을 해소한 턴에 **원래 기록의 표기도** 고친다

새 기록에 「해소됐다」만 적으면 **낡은 쪽이 `⚠️ 미확정` 으로 남아 다음 세션이 같은 것을 또 판다.**
⚠️ 실측: 이 실수를 한 세션에서 세 번 했다 — 해소 사실은 새 기록에 있는데 원래 기록 3곳이
여전히 「미확인」이었다. 그중 하나는 **이미 해소된 것을 「남은 공백」 목록에 다시 올렸다.**

```
새 기록 : 사실과 근거를 적는다
원래 기록: 그 문장을 「⭐ 해소됨(<날짜> <근거>) — <결론>. 상세는 [새 기록의 req] 참조」로 바꾼다
```

⭐ 값이 틀렸던 경우(추측을 사실로 적었다)도 같다 — **추측 문장을 그 자리에서 지운다.**
남겨두면 새 기록과 낡은 값이 함께 검색돼 어느 쪽이 참인지 다음 세션이 못 가린다.

### ⛔⛔ 과거를 소급 기록할 때 — 최신을 덮지 않는다

이력·업무목록·문서를 **최신→과거 순으로 훑을 때** 가장 위험한 실수다.
`supersedes` 는 기록 순서(줄 번호)로 판정하므로, **과거 사실을 나중에 append 하면 그것이 「최신」으로 들어앉는다.**

| 규칙 | |
|---|---|
| ⛔ **과거 기록에 `supersedes` 를 붙이지 않는다** | 대체는 **나중에 일어난 일**이 먼저 일어난 일을 무효화할 때만 쓴다 |
| ⛔ **`date` 를 반드시 그 일이 일어난 날로 준다** | 안 주면 오늘이 들어가 시간축이 뒤집힌다 |
| ⭐ **최신 기록과 어긋나면 과거 쪽에 표기한다** | 「⚠️ 이후 <날짜>에 <무엇>으로 바뀜 — 최신은 [그 기록] 참조」 |
| ⛔ **과거 사실을 용어 키로 올리지 않는다** | 죽은 기능·옛 컬럼명은 `note` 에 쓴다. 용어 키로 올리면 조회 상위를 과거가 차지한다 |

⭐ **판단 기준: 「지금 이 시점에 이 말이 참인가」** — 아니면 과거 사실이고, 그때는 **현재형으로 쓰지 않는다.**
예: 「미래혁신팀이 담당이다」(✗) → 「2026-09-03 까지는 미래혁신팀이었다, 현재는 기획팀」(✓)

## 5. 끝내기 전 — 반드시

```bash
node tools/graph-find.mjs --check    # ⛔ exit 0 이어야 한다 (사슬·경로·용어 선점·열린 작업 표식)
node tools/graph-find.mjs <방금 넣은 용어>   # 걸리는가
node tools/graph-find.mjs --open     # 하다 만 것(⏸)이 제대로 잡히나
```

⛔⛔ **하다 만 채로 끝내는 턴이면 `note` 를 `⏸` 로 시작한다.** 적어 두는 것만으로는 다음 세션이 못 찾는다 —
랭킹이 평평한 키워드 합산이라 항목이 많은 광역 기록이 도메인 낱말을 독점한다.
⚠️ 실측: 설계까지 해두고 멈춘 보류 기록이 **그 작업을 재개하는 요청**에서 10위였고, 훅·CLI 표시 한도 밖이라 닿지 못했다.
`⏸` 가 붙으면 훅이 순위와 무관하게 「⏸ 열린 작업」 줄로 붙여 준다.
⛔ 표식은 `note` **맨 앞**에서만 인정한다. 낱말(「미구현」·「보류」)로 넓히면 오탐이 생겨 기계는 후보만 올린다(`--check`).
⛔ 재개해서 끝냈으면 `supersedes` 로 무효화한다 — `⏸` 를 지우는 것으로 갈음하지 않는다.

⭐ 정본을 만들었거나 고쳤으면 `node tools/graph-measure.mjs "<현업 표현 정규식>"` 으로 그 주제에서 정본이 1위인지,
템플릿을 만들었으면 `node tools/sql-template-check.mjs <파일>` 로 컬럼이 스키마와 맞는지 확인한다.

⭐ 사용자에게 **작업 파일 목록을 보고할 때 그래프 기록도 한 세트로** 보고한다.
남길 게 없다고 판단했으면 **그 판단을 한 줄로 밝힌다** — 조용히 건너뛰지 않는다.


새 영역은 여전히 정상 탐색 비용이 든다 — 그때 용어를 등록해야 다음이 빨라진다.
