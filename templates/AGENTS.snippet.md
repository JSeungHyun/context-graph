## ⭐ 요구가 들어오면 이 순서로 탐색한다

```
1. node tools/graph-find.mjs <용어…>      ← 과거 유사 요구 + 그때 만진 파일. 있으면 시작점이 공짜다
   node tools/graph-find.mjs --with <파일>  ← 그 파일을 고칠 때 같이 움직이는 파일 (2홉)
2. <어휘 정본 문서 — 있으면. 현업 용어 → 코드 식별자>
3. <관통 조회 도구 — 있으면>
4. <규격 문서 해당 절만>
5. <정밀 탐색 — LSP MCP 가 있으면 그것, 없으면 Grep / Glob>
```

⛔ **1번을 건너뛰지 않는다.** 같은 주제를 두 번째 풀 때 처음부터 다시 탐색하는 것이 가장 큰 낭비다.
⚠️ 1번이 빈손이면 **새 영역이다.** 그때는 2번부터 정상 탐색한다.
⭐ **어근을 짧게, 여러 개 준다.** 부분일치라 조사·접미사가 붙으면 놓친다 — 「문의하기」 0건, 「문의」 3건.

### ⭐⛔ 사용자가 쓴 말이 그래프에 없으면 그 자리에서 배운다

사용자의 표현으로 조회해 **0건이면 어휘 다리가 빠진 것**이다. 코드를 파서 실체를 알아낸 뒤,
**사용자가 실제로 쓴 그 말을 키로** 기록한다. 작업이 끝나기를 기다리지 않는다 — 용어는 대화 중에 드러나고 그때 안 적으면 사라진다.

```bash
node tools/graph-alias.mjs <사용자가 쓴 말> "<시스템에서 무엇인가>" [--file 경로]… [--note 함정]
```

⛔ **키는 사용자의 말, 값은 시스템의 실체다.** 공식 용어를 키로 적으면 다음에도 똑같이 못 찾는다.
⛔ **알아내기 전에 적지 않는다.** 추측을 적으면 다음 세션이 그것을 사실로 믿는다.
⭐ 같은 것을 다르게 부르면 그때마다 한 줄씩 더 적는다. 별칭이 쌓일수록 걸리는 폭이 넓어진다.
⛔ **용어 키는 그 용어의 정본 기록에만 둔다.** 도구·설정 작업 기록에 도메인 용어를 *예시로* 넣으면
그 용어의 정본 기록을 순위에서 밀어낸다 (2026-09-04 실측 — 상위 2건 중 정본이 2위로 밀렸다).
예시는 `note` 나 `req` 본문에 쓴다. 거기도 검색되지만 가중치가 낮아 정본을 밀지 않는다.

⚠️ **조사·띄어쓰기는 저장하지 않는다.** 「재무지표가」·「재무 지표」는 질의 쪽에서 규칙으로 만든다
(`graph-hook.mjs`). 저장 쪽에 넣으면 색인이 2.7배가 되는데 새 지식은 0이다.
⇒ **규칙으로 만들 수 있으면 질의 때 만들고, 못 만들면(동의어·약어) 저장한다.**

### ⛔ 작업이 끝나면 요구 → 파일 간선을 기록한다

작업 파일 목록을 사용자에게 보고할 때 **같은 내용을 그래프에도 append 한다.**

```bash
node tools/graph-append.mjs <<'EOF'
{"req":"<사용자 요구 한 줄>",
 "terms":{"현업 용어":"시스템에서 무엇인가 (테이블·URL·컬럼·서비스)"},
 "tables":["<DB 를 만졌으면>"],
 "files":["실제로 만진 파일 경로…"],
 "note":"다음 사람이 알아야 할 함정 한 줄"}
EOF
```

⭐ **`terms` 는 객체로 쓴다** — 「경영주기 → `base_year`」처럼 **무엇을 의미하는지**까지 담는다.
배열(`["용어","용어"]`)로 쓰면 용어만 남고 해석이 사라진다.
⭐ **`note` 가 이 기록의 값이다.** 파일 목록은 git 으로도 알 수 있지만 「왜 그 파일이었나」는 여기에만 남는다.
⭐ **미구현·중단된 것도 기록한다.** 「거기까지 알아냈고 왜 멈췄나」가 다음 시도의 출발점이다.
⛔ **기록 저장소는 자동 로드되지 않는다** — `requests.jsonl` 은 조회로만 읽으므로 무한히 커져도 세션 비용이 0이다.
(훅을 붙였다면 자동으로 들어오는 것은 **저장소가 아니라 상한이 걸린 조회 결과 2건**이다. 원칙은 유지된다.)

### ⛔ 기능을 바꿔 기존 기록이 낡으면 그 자리에서 무효화한다

새 기록을 추가하는 것으로 갈음하지 않는다. **판단 기준은 「이 기록을 그대로 믿고 작업하면 틀리나」** — 틀리면 낡은 것이다.

| 낡은 것 | 할 일 |
|---|---|
| `requests.jsonl` 의 이전 기록 | 새 기록에 `"supersedes":"<이전 기록의 req>"` |
| <어휘 정본 문서> | 어긋난 줄을 고친다 |
| <규격 문서> | 근거(`파일:라인`)와 함께 반영 |

⛔ **별개 작업이면 비운다.** 같은 화면을 만졌다고 다 대체가 아니다.
⚠️ `supersedes` 는 **`req` 문자열로 잇는다** — 한 글자만 달라도 사슬이 끊긴다. `--check` 로 확인한다.
⭐ `date` 는 **세상 시간**(작업이 일어난 때), `recorded` 는 **기록 시간**(줄을 쓴 때). 과거를 소급 기록할 때만 `date` 를 직접 준다.

### 주기적으로 — 검증과 승격

```bash
node tools/graph-find.mjs --check                    # 무결성 4절 — 사슬·경로·용어 선점·시간 (이상 있으면 exit 1)
node tools/graph-find.mjs --promote <어휘 정본 문서>   # 3회 이상 등장 + 정본에 없는 용어
node tools/graph-view.mjs                            # 전체를 브라우저 한 장으로
```

⛔ **`--check` 가 낡음을 두 방향으로 잡는다.** 「경로 무결성」은 참조 경로가 사라진 기록을,
「용어 선점」은 같은 용어에서 과거 기록이 조회 1위인 것을 잡는다 — 그대로 두면 새 세션이 낡은 값을 답한다.

## ⛔ 작업 흐름 — `writing-plans` 를 쓰지 않는다

<!-- ⚠️ 이 절은 superpowers + ponytail 조합을 쓸 때만 넣는다. 안 쓰면 삭제한다. -->

```
brainstorming (superpowers)   요건·설계를 대화로 확정
      ↓  ⛔ writing-plans 생략 — 계획 문서를 만들지 않는다
구현                          ponytail 결정 사다리를 매 판단마다 적용
      ↓
검증                          <테스트 명령>  →  /ponytail-review (과설계)  →  /code-review (정확성)
```

⛔ **brainstorming 스킬은 종료 조건이 「writing-plans 호출」로 박혀 있다. 이 지침이 그것을 무효화한다.**
사용자 지침이 스킬보다 우선한다.

⚠️ **파일 5개 이상이거나 의존 순서가 있으면** `TodoWrite` 로 단계만 나열한다 — 문서는 만들지 않는다.
⭐ 계획을 없앤 대신 **판단 시점이 구현 순간으로 옮겨진다.** ponytail 의 사다리를 코드 쓰기 직전마다 밟는다:

```
1) 존재할 필요가 있나  2) 이 저장소에 이미 있나  3) 표준 라이브러리가 하나
4) 플랫폼 기본 기능인가  5) 설치된 의존성이 하나  6) 한 줄인가  7) 그다음에야 되는 최소한
```

⛔ **깎지 않는 것** — 신뢰 경계 검증 · 데이터 손실 처리 · 보안 · 접근성.
⚠️ `/ponytail-review` 는 **과설계만** 본다. **정확성 버그는 안 본다** — 테스트와 `/code-review` 가 그 몫이다.
⚠️ `/ponytail-review` 는 내장 `/simplify` 와 거의 겹친다. **둘 다 돌리지 않는다.**
⛔ **테스트 픽스처는 ponytail 지적에서 예외로 둔다.** 「투기적 추상화」 사냥에 픽스처가 걸릴 수 있는데,
판단 기준은 **「돌연변이를 넣었을 때 실패하는가」**이고 그것은 ponytail 이 보지 않는 축이다.
⚠️ 룰셋은 **세션 시작 시** 주입된다(매 턴이 아니다). 매 프롬프트에 도는 것은 모드 추적 훅이라 비용이 토큰이 아니라 **지연**이다.
⭐ **모드는 user 스코프**(`~/.claude/settings.json` 의 `env.PONYTAIL_DEFAULT_MODE`)다 — 프로젝트마다 설정하지 않는다.
