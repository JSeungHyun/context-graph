# context-graph

**요구 → 용어·DB·파일 간선을 기록해, 다음에 같은 주제가 오면 탐색을 건너뛴다.**

의존성 0 (Node 내장 모듈만) · 스크립트 7개 · **임베딩·벡터 DB 없음.**

```
요구 도착  →  훅이 조회를 대신 돌려 상위 2건 주입   →  (있으면 시작점이 공짜)
              걸렸어도 답이 아니면 그렇다고 말하고    →  평소대로 코드 탐색
              확신이 없으면 압축 색인으로 모델이 고름 →  그래도 없으면 평소대로 코드 탐색
              신호가 약하면(0건·최고점수≤2) 침묵    →  ⛔ 그래프는 코드 탐색을 막지 않는다
대화 중    →  사용자가 쓴 말이 0건이면 알아낸 뒤 graph-alias 로 그 말을 등록
작업 종료  →  graph-append 로 간선 기록
주기적으로 →  --check 무결성 · --promote 용어 승격 · graph-view 열람
```

## ⭐ 학습 루프 — 이게 핵심이다

사용자는 자기가 어떤 말을 쓰는지 미리 모른다. **대화하면서 쌓는다.**

```
사용자: "목표수립에 재무지표가 안 보여"
  → graph-find 재무지표  →  0건        ⇒ 어휘 다리가 빠졌다
  → 코드를 파서 실체를 알아낸다
  → node tools/graph-alias.mjs 재무지표 "fin_view_type=='Y' 일 때 tableau_fin_url 또는 fin_img_path" \
       --note "소스가 기간으로 갈린다 — 수립기간 중엔 저장 이미지, 종료 후엔 태블로 라이브"
  → 다음부터 「재무지표」·「태블로」 어느 쪽으로 물어도 함정까지 같이 나온다
```

⚠️ **실측(2026-09-04)** — 위 흐름을 그대로 돌린 뒤, 컨텍스트가 전혀 없는 새 세션에 도구를 금지하고
「수립기간 중인데 태블로가 안 뜬다, 버그인가?」를 물었더니 **「버그 아님. 기간 중엔 저장 이미지를 쓰도록 설계됨」**
이라고 답했다. 3분 전 대화에서 배운 것이다.

⛔ **키는 사용자의 말, 값은 시스템의 실체다.** 공식 용어를 키로 적으면 다음에도 똑같이 못 찾는다.

## 구성

| | |
|---|---|
| `SETUP.md` | ⭐ Claude Code 에게 주는 설치 지시서 |
| `templates/AGENTS.snippet.md` | 대상 `AGENTS.md` 에 추가할 절 (⛔ `<…>` 를 채워서 써야 한다) |
| `tools/graph-append.mjs` | 기록 추가 (stdin JSON · JSONL 다건 가능) |
| `tools/graph-find.mjs` | 조회 — 용어·파일 양방향, `--with` 2홉, `--check` 무결성, `--promote` 승격 후보 |
| `tools/graph-alias.mjs` | ⭐ 대화 중 알아낸 「사용자의 말 → 실체」를 한 줄로 기록 (별도 저장소 아님 — 같은 JSONL) |
| `tools/graph-hook.mjs` | ⚠️ 선택 — `UserPromptSubmit` 훅. **1단** 키워드 상위 2건 → **2단** 압축 색인 → 안 걸리면 **침묵**. 두 단 모두 「답이 아니면 코드로 가라」를 명시한다 |
| `tools/graph-view.mjs` | 전체를 브라우저 한 장(HTML)으로 굽는다. 데이터를 박지 않고 매번 생성 |
| `tools/commit-index.mjs` | 커밋에서 어휘·쌍 비대칭·열지도 추출 (⚠️ 한국어 불용어 하드코딩) |
| `tools/spec-toc.mjs` | 큰 마크다운의 `##` 절별 라인 범위 (부분 로드용) |

## 사용

```bash
# 조회
node tools/graph-find.mjs 경영주기 차수            # 용어로 (어근을 짧게, 여러 개)
node tools/graph-find.mjs --files GoalSettingDao   # 파일 → 그 파일을 만진 요구 (1홉)
node tools/graph-find.mjs --with  goal_popup_set   # 파일 → 같이 움직이는 파일 (2홉)
node tools/graph-find.mjs --check                  # 무결성 4절 — 사슬·경로·용어 선점·시간 (이상 있으면 exit 1)
node tools/graph-find.mjs --promote spec-map.md    # 승격 후보 (3회 이상 · 정본에 없는 것)
node tools/graph-view.mjs                          # 브라우저 열람용 HTML 생성

# 기록
node tools/graph-append.mjs <<'EOF'
{"req":"목표승인 반려가 목록에 안 뜬다",
 "terms":{"목표승인":"/goal/goal_setting_main_appr.do","반려":"reject_flag (goal_step_info_new)"},
 "tables":["apms.goal_step_info_new"],
 "files":["src/main/java/.../GoalSettingController.java","view/goal/goal_list_appr.jsp"],
 "note":"국내/해외 JSP 짝이 있다 — 한쪽만 고치면 해외에서 안 먹는다"}
EOF
```

⚠️ **`--with` 는 git 으로 거의 재현된다.** 실측(2026-09-04): `git log --name-only` 로 같은 파일을 세면
`goal_popup_appr.jsp 4/6`, ko/en `3/6` 이 나온다. 그래프는 `4/4` 로 더 또렷하지만(커밋이 아니라 **작업 단위**라
한 작업의 5개 커밋이 1건으로 세어진다) **차이는 선명도이지 정보의 유무가 아니다.**

⇒ `--with` 를 도입 근거로 삼지 않는다. 편의 기능이다.

## ⛔ 설계 원칙 — 이걸 어기면 목적과 반대가 된다

| 원칙 | 왜 |
|---|---|
| **저장소를 자동 로드하지 않는다** | 자동 로드되는 층은 쌓일수록 매 세션 비용이 된다. 조회로만 읽는다 |
| **훅이 넣는 것은 저장소가 아니라 상한이 걸린 결과** | 상위 2건 고정이라 기록이 1,000건이 돼도 주입량은 그대로다 |
| **변하는 것은 조회하고 안 변하는 것만 적는다** | 재생성 가능한 값(파일 목록·건수) 대신 **명령**을 적는다 |
| **검증 안 된 것을 적지 않는다** | 틀린 기억은 없는 기억보다 나쁘다 — 믿고 재확인을 건너뛴다 |
| **자동 추출하지 않는다** | 검증 관문이 없다. 사람 판단을 거쳐 기록한다 |
| **저장소를 하나로** | 메모리 저장소가 둘이면 반드시 어긋난다 |

## 이 저장소에 없는 것 — 의도적이다

⛔ **관통 추적기(`trace.mjs`)는 포함하지 않았다.** APMS 의 Spring MVC + JSP + MyBatis 명명 규약
(`@RequestMapping` → `return "a/b"` → `xxxDao.method()` → 매퍼 `id`)에 묶여 있어 다른 스택에서 안 돈다.

⇒ 대상 프로젝트의 구조가 기계적으로 성립하면 **그 프로젝트용으로 새로 만드는 것**이 맞다.
APMS 판은 `C:\Project\apms\tools\trace.mjs` 에 있으니 참고할 수 있다.

⛔ **벡터 임베딩도 없다.** 실패는 검색 성능이 아니라 **어휘**에서 난다 — 「필실천」으로 grep 하면 0건이고
코드엔 `eap` 뿐이다. 그 다리는 사람이 놓아야 하고, 놓고 나면 부분일치로 충분하다.

## 왜 JSONL 인가 — 외부 근거

그래프 DB 벤치마크 기준으로 **10만 간선 미만이면 JSONL 이 적합**하고, 100만을 넘어야 직접 만든 도구의
유지비가 DB 비용을 넘는다. 실측한 APMS 그래프는 기록 30건에 **간선 215개 — 상한의 0.2%** 다.

다만 같은 벤치마크에서 **JSONL 의 다중홉 질의 점수는 3/10**(Neo4j 10)이다.
⇒ **약점은 저장이 아니라 질의였다.** 그래서 DB 를 넣는 대신 `--with`(2홉)·`--check`(사슬 순회)를 코드로 넣었다.
215 간선에서 메모리 내 순회는 마이크로초라 DB 가 할 일이 없다.

- [Neo4j vs Postgres+AGE vs JSONL](https://mohammadshaker.com/en/blog/neo4j-vs-postgres-age-vs-jsonl-graph-data-showdown)
- [Zep: 시간 지식 그래프의 bi-temporal 모델](https://www.getzep.com/ai-agents/temporal-knowledge-graph/) — `date`/`recorded` 분리의 근거
- [From Fragments to Paths (arXiv)](https://arxiv.org/pdf/2606.22906) — **작업 층과 코드 구조 층은 다르다.** 구조 분석만으로는 변경의 의도를 못 얻는다

## ⛔ 정직한 값 — git 이 이미 가진 것과 아닌 것

**외부 검토(2026-09-04, 이 도구를 만들지 않은 판정자)의 결론은 「축소」였다.** 그 지적이 옳고, 아래가 그 반영이다.

| 차원 | git 으로 되나 | 판정 |
|---|---|---|
| 작업이 만진 파일 목록 | ✅ `git log --name-only` | ⛔ **고유값 아님** |
| 동반변경 빈도 (`--with`) | ✅ 거의 동일 (4/6 vs 4/4) | ⛔ **고유값 아님 — 편의 기능** |
| 언제 무엇이 바뀌었나 | ✅ 커밋 이력 | ⛔ **고유값 아님** |
| **현업 용어 → 코드 식별자** | ❌ 어디에도 없다 | ⭐ **이것이 핵심** |
| **함정 한 줄 (왜 그 파일이었나·무엇에 걸렸나)** | ❌ 한 줄 커밋 메시지에 안 들어간다 | ⭐ **이것이 핵심** |
| 이 기록이 이제 틀렸다는 판단 (`supersedes`) | ❌ 사람의 판정이다 | ⭐ 고유값 |

⇒ **`terms` 와 `note` 를 대충 적으면 이 저장소는 git 의 열등한 사본이다.** 파일 목록만 쌓는 것은 값이 0이다.

## ⛔ 도입하지 말아야 할 때

| 이럴 땐 하지 않는다 | 왜 |
|---|---|
| 프로젝트 수명이 몇 주다 | 20~30건 누적 전에 끝난다. 그 구간의 이득은 0이다 |
| 혼자서 한 도메인만 계속 만진다 | 어휘 다리가 이미 머릿속에 있다 |
| 현업 용어와 코드 식별자가 같다 (영어 프로젝트 다수) | 핵심 값의 절반이 사라진다 |
| 작업 종료 시 기록할 규율을 지킬 자신이 없다 | ⛔ **가장 약한 고리** — 아래 참조 |

### ⛔ 가장 약한 고리 — 수동 기록

읽기(조회)는 훅으로 자동화되지만 **쓰기(append)는 끝까지 사람이 한다.** 규율이 흐트러지면 그래프는
비어가는 게 아니라 **낡아간다** — 그러면 「확신에 찬 틀린 정보」를 내놓는 상태가 되고, 이건 없느니만 못하다.

완화책은 세 개고 셋 다 완전하지 않다:

- `--check` 의 **경로 무결성** — 참조 파일이 사라졌으면 그 기록이 낡았다는 신호다. 리팩터링은 잡지만 의미 변화는 못 잡는다.
  ⛔ **대체된 기록은 제외하고 본다** — 경로가 없어진 것이 바로 대체된 이유인 경우가 많아 안 그러면 영구 오탐이 된다
- `--check` 의 **용어 선점** — 같은 용어를 여러 기록이 가질 때 **과거가 조회 1위면** 새 세션이 낡은 값을 그대로 답한다.
  ⚠️ 「최신이 1위인가」까지만 본다. **「값이 낡았는지」는 기계가 판정 못 한다**
  ⛔ **이 검사는 용어 키가 겹칠 때만 본다.** 자유 검색어(용어 키가 아닌 말)로 물으면 통과한 채로 대체된 기록이 1위에 앉는다 —
  그래서 조회 정렬에서 **동점이면 살아있는 기록을 앞에 둔다**(2026-09-08 추가). 그 전에는 낡은 기록의 `terms` 를 손으로 비워야 했다
- `supersedes` — 사람이 낡음을 선언해야 한다. **선언을 안 하면 못 잡는다**

⚠️ **경고는 드물어야 신호다.** `--check` 가 늘 exit 1 이면 사람이 무시하게 되고, 그러면 검사가 없는 것과 같다.

⚠️ **자동 추출로 이 구멍을 메우려 하지 않는다.** 검증 관문이 없는 자동 기록은 낡은 정보를 더 빨리 쌓을 뿐이다.
